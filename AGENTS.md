# Complementos técnicos de Conversor_3D

## Vigencia y lectura de instrucciones

El texto anterior reproduce íntegramente y de forma literal el documento V2.3.1
aprobado por el usuario para este proyecto el 13 de noviembre de 2026.
La V2.3.1 rige el método general. Los apartados siguientes y `visor/AGENTS.md`
conservan las instrucciones técnicas compatibles del programa; no amplían las
autorizaciones para cambiar arquitectura, integrar motores o aprobar versiones.

## Ámbito de los productos y rama de trabajo

El conversor web de `index.html` y `static/` es distinto del Visor completo
Python/OCP para Windows. El desarrollo incremental del Visor vive en `visor/`.
La rama de trabajo actual es `perfeccion_Visualizador_R21`;
R20 permanece en `perfeccion_Visualizador_R20`;
`desarrollo/hoja-ruta-visor` contiene el desarrollo previo a la entrega R20.
Comprobar siempre la rama y el estado reales antes de continuar.

Antes de cualquier tarea del Visor, leer también `visor/AGENTS.md`, incluso
cuando los archivos afectados sean lanzadores de la raíz o estén en `entregas/`.
Trabajar en el Visor no autoriza modificar el conversor web ni sus automatizaciones.

## Versiones y fixtures conservados

Tras la limpieza autorizada, el árbol activo conserva R18, R19, R20 y la
corrección del instalador R19. Las versiones anteriores se recuperan desde Git
y sus ramas; el inventario está en `MANTENIMIENTO_VERSIONES.md`.
Las pruebas históricas usan los seis archivos originales con hashes en
`visor/test-data/r5_regression.zip`, no la entrega completa R5. Esta carpeta de
datos queda fuera de los ZIP de producto. Conservar los 357 archivos R19 y
los checksums de los paquetes R18/R19/R20 que siguen publicados.

## Conversor web: instrucciones técnicas conservadas

Estas reglas corresponden exclusivamente al producto web y no convierten el
Visor para Windows en una aplicación estática:

- La aplicación debe abrirse mediante un enlace web, sin instalar programas. Mantener el flujo completamente estático con HTML, JavaScript y WebAssembly.
- Probar el flujo real en navegador y la lectura de los STEP exportados. No describir pruebas del antiguo backend como validación de la conversión WebAssembly.
- Mantener la interfaz en español y un uso simple.
- No presentar STEP facetado como reconstrucción paramétrica ni prometer perfección para STL arbitrarios.
